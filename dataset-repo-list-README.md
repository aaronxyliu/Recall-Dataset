tsc CLI 在调查中属于构建工具。本数据集将普通 TypeScript 编译、类型检查和声明文件生成排除在前端打包分组之外。

SWC 的 spack 具备打包功能。筛选到的可验证公开页面中，SWC 用作转译器，或只构建独立 worker，未找到足以归入此组的前端生产构建。 [SWC 的打包文档](https://swc.rs/docs/usage/bundling)

GitHub 仓库搜索使用星标降序，另通过公开代码索引补查未在仓库描述里写明打包器的项目。排名覆盖本次筛选通过的样本。核对 package.json 的生产构建命令，并在需要时追到配置或发布脚本。公开入口须返回 HTML，可包含公开登录页、互动演示和项目站点。

普通 vite build 归入 Vite，JSON 中的 bundlingEngine 字段另记底层引擎。Vite 4–7 的生产打包默认走 Rollup，Vite 8 默认走 Rolldown。直接执行 Rolldown 或清单明确使用 rolldown-vite 别名的站点归入 Rolldown。[Vite 迁移文档](https://vite.dev/guide/migration.html)

Next.js 按生产命令与版本判断。Next.js 16 的 next build 默认使用 Turbopack，--webpack 显式选择 webpack。Angular 依据构建目标的 builder 判断，application 对应 esbuild，browser 对应 webpack。[Next.js 16 文档](https://nextjs.org/docs/app/guides/upgrading/version-16) · [Angular 构建文档](https://angular.dev/tools/cli/build) · [tsup 的 esbuild 说明](https://github.com/egoist/tsup#tsup)

源码证据固定到 GitHub 提交，线上检查记录页面响应和可见脚本地址。线上服务通常不公开部署 SHA，因此分类描述可复核的源码构建。若线上资源与源码构建明确冲突则排除，例如 rahuldkjain/github-profile-readme-generator 的公开页面仍加载 webpack-runtime，而当前清单指定 next build --turbo。本次检查未逐一重建或操作网页功能。
